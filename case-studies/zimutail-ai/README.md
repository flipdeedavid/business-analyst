# Zimutail AI

## Improving Clothing Fit Through AI-Powered Sizing

**Role:** Product Manager | Business Analyst

### Problem

Customers can struggle to select the right clothing size online. Poor fit can create friction for shoppers and contribute to returns. Sellers also need a consistent way to map their size charts into a sizing experience.

### Users

- Online shoppers
- Fashion sellers
- Seller administrators
- Micro-sellers

### Product Direction

A B2B seller-paid plugin / white-label SDK and kiosk concept supporting:

- Camera-based measurement
- Tape-measure entry
- Height and weight quick entry
- Seller size-chart mapping
- Fit recommendations

Sizing logic was designed to support configurable fit preferences including slim, regular, leisure and maternity use cases.

### What I Did

**Discovery → stakeholder alignment → requirements analysis → user flows → sizing logic → MVP definition → backlog → acceptance criteria → cross-functional delivery**

I also worked through inconsistencies between PRD, frontend and backend measurement fields.

### Scope Decisions

- Ready-made clothing remained in scope; tailoring did not.
- Virtual try-on was deferred.
- Inventory/AI demand forecasting was outside the immediate scope.
- Low-spec mobile devices were considered.
- Server-side ML was considered where device limitations affect the experience.

### Artefacts

PRD | Personas | User flows | Customer/seller journeys | Product scope | Sizing rules | Backlog | Acceptance criteria

### Outcome

A clearer product direction and set of requirements were established around customer and seller experiences, including scope boundaries and specification gaps.

The target was approximately **90% sizing accuracy**; this is a product target, not a measured achieved result.

### Learning

AI products require strong alignment between product requirements, UX, frontend, backend and ML assumptions. Defining the data model and measurement vocabulary early reduces ambiguity.
